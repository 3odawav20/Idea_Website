# IDEA — حسابات العملاء والشركات والوارد والصادر على cPanel

الواجهة React/Vite، والحسابات الجديدة والمنتجات وعروض الأسعار تعمل باستخدام **PHP 8.1+ وMySQL على cPanel**. لا تحتاج ربط حساب Supabase أو OAuth لتشغيل هذه الوظائف. ملفات Supabase القديمة في المستودع ليست خطوات إعداد لهذا التسليم.

## تركيب الموقع

1. من cPanel > MySQL Database Wizard أنشئ قاعدة ومستخدمًا وأضفه للقاعدة بالصلاحيات اللازمة.
2. افتح phpMyAdmin واستورد `database/mysql-accounts.sql`. الجداول تبدأ بـ `idea_` ولا تستبدل جداول أخرى.
3. انسخ `idea-accounts-config.example.php` **خارج** `public_html` باسم `idea-accounts-config.php`، مثل `/home/CPANEL_USER/idea-accounts-config.php`. أدخل اسم قاعدة MySQL واسم المستخدم وكلمة المرور. اضبط `site_url` على الدومين الفعلي و`mail_from` على بريد تملكه داخل الاستضافة. يمكن تحديد المسار بمتغير PHP `IDEA_ACCOUNTS_CONFIG` عند استخدام document root مختلف.
4. ارفع محتويات `cpanel-upload.zip` إلى جذر `public_html`. الحزمة تتضمن ملفات `.htaccess` وواجهات PHP. لا تحتاج Node.js على الاستضافة بعد البناء.
5. فعّل HTTPS، وإضافات PHP `pdo_mysql` و`fileinfo`، واسمح بالكتابة داخل `uploads/company-products`. لا ترفع ملفات إعداد الاتصال الحقيقية إلى GitHub أو مجلد الموقع العام.
6. جرّب الحسابات والرفع والبريد على الدومين الفعلي. رابط استعادة كلمة المرور يرسل بواسطة بريد PHP `mail()`؛ يلزم إعداد إرسال البريد على cPanel واختبار الاستلام.

## ثلاثة أنواع من الحسابات

- **العميل**: تسجيل مستقل، اشتراك أساسي مجاني، مفضلة، سلة طلبات أسعار، وارد عروض الموردين وصادر الطلبات، ومعاينة الغرفة.
- **الشركة / المورد**: تسجيل مختلف يتضمن اسم الشركة ومسؤول التواصل والسجل/الرقم الضريبي الاختياريين، واستبيان المنتجات والتخصص الرئيسي ونوع النشاط ومتوسط قيمة التعاقد والمحافظات ومناطق التوريد والعلامات وقدرة التوريد والحد الأدنى للطلب وسنوات النشاط ورابط الشركة. تظهر الإجابات الخاصة للإدارة وصاحب الحساب، ولا تدخل في واجهة المتجر العامة.
- **الإدارة**: تعتمد الشركات أو ترفضها أو توقفها، وتراجع بياناتها ومنتجاتها وطلبات العملاء وعروض الموردين، وترسل ردًا لحساب العميل أو الشركة. تسجيل العميل/الشركة لا يمنح صلاحية إدارة.

لإنشاء أول مدير: أنشئ حسابًا من الموقع، ثم غيّر **هذا الحساب المحدد فقط** من phpMyAdmin:

```sql
UPDATE idea_users SET role = 'admin' WHERE email = 'YOUR_ADMIN_EMAIL';
```

استبدل البريد ببريد المدير المقصود وتأكد من تعديل صف واحد، ثم أعد تسجيل الدخول. لوحة الإدارة في `/admin`.

## المنتجات وطلبات الأسعار

1. الشركة ترفع صورة المنتج ومواصفاته في `/business/products`. المنتجات تحفظ كمسودات حتى اعتماد الشركة ثم نشرها.
2. ربط منتج الشركة بكود من كتالوج IDEA يجعل طلب المنتج يصل إلى **جميع الشركات المعتمدة التي نشرت نفس الكود**. للمنتجات الخاصة، المطابقة حسب الاسم والماركة والخامة والمقاسات بعد توحيد المسافات وحالة الحروف؛ اختلاف البيانات يعني منتجًا مختلفًا، وليس مطابقة تقريبية مضمونة.
3. العميل يضغط أيقونة السلة على المنتج، ويفتح `/request-quote/new` ويحدد الكمية ووحدة م² أو قطعة أو طن أو كجم، ثم يرسل الطلب.
4. يسجل السيرفر المستلمين مرة واحدة لكل شركة ويضع الطلب في وارد الشركات المطابقة. عند عدم وجود مورد مطابق، يبقى الطلب محفوظًا مع رسالة واضحة. إذا نُشر منتج مطابق خلال مدة الطلب، يصله الطلب المفتوح أيضًا.
5. المورد يرد من `/business/inbox` بسعر الوحدة والكمية والشحن والضريبة ومدة التسليم وصلاحية العرض والملاحظات. السيرفر يحسب الإجمالي، ويعرض الرد في صادر المورد ووارد العميل. لا يرى المورد عروض منافسيه.
6. العميل يقارن بيانات العروض في `/account/inbox` ويتابع طلباته في `/account/outbox`. لوحة الإدارة تعرض الطلبات والعروض وتدعم الردود الإدارية.

هذه **طلبات وعروض أسعار**؛ لا يتم اختلاق دفع أو فاتورة أو طلب شراء مدفوع. أسعار الاشتراكات المدفوعة وبوابة الدفع تحتاج إعدادًا منفصلًا؛ الاشتراك الحالي يسجل نوع الحساب وتفضيل شهري/سنوي ولا يخصم أموالًا.

## اللغة والخط

AR يغيّر اتجاه الواجهة إلى RTL وEN إلى LTR، والاختيار محفوظ تحت `idea.locale`. القاموس الإضافي في `src/app/i18n/ui-pairs.json`. الخط المحلي Cairo موحد للغتين ولأزرار وحقول الإدخال. أسماء موديلات المنتجات والعلامات وبيانات المستخدمين تبقى كما أُدخلت. هندسة الصور ومؤشر المقارنة يحتفظان بإحداثيات LTR.

## التحقق وحدود التسليم

- `npm run build` لبناء ملفات cPanel.
- `npm run test:studio` لاختبارات المتصفح، ومنها فصل استمارات التسجيل وإرسال الاستبيان واللغة والمقاسات ورفع المسودات والاستوديو. بعض طلبات API فيها اعتراضات محلية للاختبار.
- `npm run test:accounts` لاختبار PHP الفعلي، جلسات الدخول والأدوار وحفظ الاستبيان واعتماد الشركات والمطابقة والرسائل والإجماليات. يحتاج خادم PHP محليًا وfixture الاختبار.
- `scripts/prepare-account-test.php` ينشئ قاعدة SQLite **للاختبار المحلي فقط**. وضع SQLite لا يعمل إلا مع PHP `cli-server` ومتغير البيئة الخاص بالاختبار. إنتاج cPanel يستخدم MySQL. لم يتم توفير بيانات cPanel/MySQL الفعلية، لذلك لا يوجد ادعاء باختبار قاعدة الإنتاج أو نشر الموقع على الاستضافة.
- `scripts/test-native-quotation-ui.mjs` يفحص المسار في متصفح حقيقي: منتج ← سلة ← كمية ووحدة ← وارد المورد ← الرد بالسعر ← وارد العميل ← لوحة المدير.
- `scripts/visual-native-accounts.mjs` يلتقط شاشات الحسابات بالعربي والإنجليزي وعلى المحمول. ملفات fixture والحسابات التجريبية والصور الخاصة لا تدخل Git أو حزمة النشر.

توليد الصور الحقيقي يحتاج مفتاح خدمة الصور على السيرفر كما في دليل الاستوديو. صورة الغرفة المحفوظة في المعاينة المحلية ليست إثباتًا على تفعيل التوليد في الإنتاج.
